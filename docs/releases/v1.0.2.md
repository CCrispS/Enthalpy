# Enthalpy v1.0.2

修复版：剪影在“没有渲染层的地图”上不再消失，斜坡上拖列队不再卡顿，取形状也不会再把被借用单位的倾斜角留在真单位身上。

RA3-style formation orders for **Command & Conquer: Yuri's Revenge 1.001** — hold the middle mouse button at the destination, drag to shape the block, release to move and turn every selected unit exactly where the translucent silhouettes were shown.

## 本版修复 / Fixed in this release

- **有的地图完全不显示剪影**：引擎里能画剪影的只有两个地址，其中 `0x6D9134` 只在地图**有渲染层**时才会执行，纯沙地这类地图根本走不到，于是 `DrawPreview()` 一次都没被调用。现在同时挂 `0x6D9076`（渲染层起点，每帧必走）作为第二条路径，并在每一帧实测“上一帧最后执行的是哪个点”，让最后执行的负责落笔。
- **斜坡上拖列队严重卡顿**：取形状要保存/填充/比对/还原约 40 万像素，旧实现每像素一次 `Surface::GetPixel`/`SetPixel` 虚调用，单次捕获 19.8 / 10.0 / 6.6 ms，按每帧 3 个新剪影算就是单帧 30–60 ms。现在通过 `Surface::Lock` 直接读 16 位缓冲，单次捕获降到 **1.34 / 0.63 ms**。斜坡更明显的原因也一并说明：缓存键含坡度，平地只有 3 个键，坡面每格不同会让 48 条缓存持续淘汰、每帧重新捕获。
- **剪影把真单位也带歪了**：取形状时会临时把被借用单位的移动控制器切到目的地格坡度（`ILocomotion::Force_New_Slope`），旧代码只还原坐标与朝向，**没还原坡度**；这个状态黏在移动控制器上，于是被借用的单位（往往正是玩家选中的那批）会一直保持剪影的倾斜角。现在两次绘制后立刻还原该单位脚下格子的真实坡度，并且优先借用**未被选中**的同类型单位。

## 安装 / Install

1. 把 `Enthalpy.dll` 和 `Enthalpy.ini` 放进游戏根目录（与 `gamemd.exe` 同级）。
2. 用 Syringe / SyringeEx 加载：`Syringe.exe -i=Enthalpy.dll gamemd.exe`，或在 `Resources\ClientDefinitions.ini` 的 `ExtraCommandLineParams` 里追加 `-i=Enthalpy.dll`，或直接让 SyringeEx 的 `*.dll` 扫描自动识别。
3. 进入游戏，左键选中单位 → 在目的地按住中键拖动 → 松手。

## 升级说明 / Upgrade notes

- 直接覆盖旧的 `Enthalpy.dll` 即可；`Enthalpy.ini` 若有自定义键请保留原文件（本版没有新增或改名任何配置键）。
- 视觉效果与 v1.0.1 一致，本版只修行为与性能。

## 要求 / Requirements

- Yuri's Revenge 1.001（`gamemd.exe` 标准版），32 位。
- Syringe 0.7.x 或 SyringeEx 0.1.x。
- 可选：Ares 3.0p1、Phobos（本插件不依赖其内部结构，但会与其共存）。
- 构建：Visual Studio 2022+，Win32，`Enthalpy.vcxproj`（Release 默认 `/MT`，无 VC 运行库依赖）。

## 已知限制 / Known limitations

- 剪影是“借引擎画一遍再取差集”得到的位图，按 `(类型, 朝向档, 坡度格)` 缓存；极端视角下某些朝向的体素剪影会偏窄。
- 剪影绘制在物体层之前，因此当预览格上正好站着单位时会被该单位盖住。
- 飞行单位的剪影高度取 `RulesClass` 的 `FlightLevel` / `CruiseHeight` / `HoverHeight` 估算，悬停时可能与实际绘制略有差异。
- 步兵剪影固定用“就绪帧”，不跟随行走动画。
